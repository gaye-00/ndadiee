# Preuves fonctionnelles

## Fonctions repérées dans le dépôt

Les pages et routes du frontend identifient les domaines de parcours suivants :

- inscription et connexion ;
- vitrine et pages de projets, profils et annonces ;
- forum, sujets et réponses ;
- workspace et sections d’équipe ;
- hackathons ;
- revues de pull requests ;
- messagerie et notifications ;
- administration/modération.

Références : [routes frontend](../../frontend/src/router/index.tsx), [pages frontend](../../frontend/src/pages), [documentation fonctionnelle](../03-fonctionnalites/README.md), [API](../04-api/README.md).

## Niveau de preuve

Ces références prouvent que des routes et du code fonctionnel sont présents dans le dépôt. Elles ne prouvent pas :

- que les fonctions sont publiées sur Internet ;
- qu’elles ont été testées avec des utilisateurs finaux ;
- que les services externes sont correctement configurés en production ;
- qu’un parcours complet fonctionne sur l’instance de démonstration.

## À collecter pour la candidature

Pour chaque parcours retenu, archiver :

1. URL de l’environnement utilisé et date/heure du test ;
2. compte de démonstration non sensible ou procédure de création ;
3. étapes suivies et résultat attendu/observé ;
4. capture d’écran ou courte vidéo avec consentement et sans secret visible ;
5. réponse API/log anonymisé en cas de démonstration technique ;
6. résultat des tests automatisés liés au parcours.

## Parcours recommandés pour la démonstration

- créer un compte et renseigner son profil ;
- découvrir et publier un projet ;
- rejoindre une équipe ou répondre à une annonce ;
- poser une question et interagir dans le forum ;
- examiner une pull request ou une discussion d’équipe ;
- ouvrir une conversation privée ;
- montrer au moins une fonction qui sert le contexte d’usage visé par l’équipe.

La disponibilité réelle de chaque parcours en ligne reste à confirmer.
