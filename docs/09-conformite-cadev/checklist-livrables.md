# Checklist des livrables

Le cadre et la liste ci-dessous sont ceux transmis par l’équipe. Chaque case doit être cochée avec une preuve réelle avant de présenter le dossier comme complet.

## Dépôt Git

- [ ] URL du dépôt fournie au jury.
- [ ] Accès vérifié depuis un compte externe à l’équipe.
- [ ] Branche/tag remis identifié et reproductible.
- [ ] Aucun secret ou fichier `.env` réel dans l’historique partageable.
- [ ] README et index documentaires vérifiés.
- [ ] Conflits/incohérences de documentation corrigés.

## Démonstration en ligne

- [ ] URL publique HTTPS indiquée.
- [ ] Tests d’accès réalisés depuis un réseau externe.
- [ ] Frontend et API répondent sur leur domaine public.
- [ ] Inscription/connexion et parcours métier testés.
- [ ] WebSocket et médias testés si inclus dans le scénario.
- [ ] Captures d’écran/vidéo datées archivées, sans données sensibles.

## Projet hébergé et utilisable

- [ ] Hébergeur réel et environnement identifié.
- [ ] Datacloud confirmé par une preuve si requis par le cadre complet.
- [ ] Base persistante, sauvegardes et procédure de restauration vérifiées.
- [ ] Secrets injectés de façon sécurisée.
- [ ] Domaine, TLS, CORS et accès réseau contrôlés.
- [ ] Procédure de redémarrage, mise à jour et retour arrière documentée.

## Déclarations et conformité

- [ ] Composition de l’équipe confirmée (2 à 5 selon le cadre transmis).
- [ ] Contributions individuelles validées par chaque membre.
- [ ] Déclaration d’utilisation de l’IA confirmée par tous les membres.
- [ ] Inventaire de licences directes et transitives terminé.
- [ ] Dépendances et éléments médias vérifiés selon les règles effectives du concours.

## Préparation de la présentation

- [ ] Scénario de démonstration répété sur l’instance en ligne.
- [ ] Plan de secours préparé (vidéo/captures) sans remplacer l’URL si celle-ci est exigée.
- [ ] Chaque membre sait expliquer son périmètre et les limites du produit.
- [ ] Les affirmations sur utilisateurs, impact et originalité sont étayées par des preuves.
